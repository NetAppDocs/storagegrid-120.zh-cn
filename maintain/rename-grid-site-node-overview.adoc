= 使用 StorageGRID 重命名过程
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
根据需要，可以更改整个网格管理器中显示的整个网格、每个站点和每个节点的显示名称。您可以随时安全地更新显示名称。



[[what-is-the-rename-procedure]]
== 什么是重命名过程？

最初安装 StorageGRID 时，您需要为网格、每个站点和每个节点指定名称。这些初始名称称为_系统名称_，它们是最初在整个 StorageGRID 中显示的名称。

内部 StorageGRID 操作需要系统名称，因此无法更改。但是，您可以使用重命名过程为网格、每个站点和每个节点定义新的_显示名称_。这些显示名称显示在 StorageGRID 的不同位置，而不是（或在某些情况下，除了）底层系统名称。

使用重命名过程更正拼写错误，实现不同的命名约定，或指示站点及其所有节点已被重新定位。与系统名称不同，显示名称可以随时更新，而不会影响 StorageGRID 操作。

[[display-name-requirements]]
== 显示名称要求

在使用此程序之前，请查看显示名称的要求。



[[display-names-for-nodes]]
=== 显示节点的名称

节点的显示名称必须遵循以下规则：

* 必须在您的 StorageGRID 系统中保持唯一性。
* 不能与 StorageGRID 系统中任何其他项目的系统名称相同。
* 必须至少包含 1 个且不超过 32 个字符。
* 可以包含数字、连字符(-)以及大写和小写字母。
* 可以以字母或数字开头或结尾，但不能以连字符开头或结尾。
* 不能全为数字。
* 不区分大小写。例如， `DC1-ADM` 和  `dc1-adm` 被视为重复项。


您可以使用以前由其他节点使用的显示名称重命名节点，前提是重命名不会导致重复的显示名称或系统名称。



[[display-names-for-grid-and-sites]]
=== 网格和站点的显示名称

网格和站点的显示名称遵循相同的规则，但以下情况除外：

* 可以包含空格。
* 可以包含以下特殊字符： `= - _ : , . @ !`
* 可以使用特殊字符（包括连字符）开始和结束。
* 可以是所有数字或特殊字符。




[[display-name-best-practices]]
== 显示名称最佳实践

如果您计划重命名多个项目，请在使用此过程之前记录您的一般命名方案。制定一个系统，确保名称唯一、一致且一目了然。

您可以使用任何符合组织要求的命名约定。请考虑以下基本建议，了解应包括哪些内容：

* *站点指示器*：如果有多个站点，请为每个节点名称添加一个站点代码。
* *节点类型*：节点名称通常表示节点的类型。您可以使用缩写，如 `s`、 `adm` 和 `gw`（存储节点、管理节点和网关节点）。
* *节点编号*：如果站点包含多个特定类型的节点，请为每个节点的名称添加唯一的编号。


在为可能随时间而变化的名称添加具体细节之前，请三思而后行。例如，请勿在节点名称中包含 IP 地址，因为这些地址可以更改。同样，如果您移动设备或升级硬件，机架位置或设备型号可能会发生变化。

** `dc2-adm2`

** `dc2-s3`


* *第三个站点*： `Data Center 3`
+
** `dc3-s1`
